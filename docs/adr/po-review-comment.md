# PO业务评审意见记录
> PO对实验3产出物的业务审核，只评审业务逻辑，不评审技术实现

## 1. 聚合评审意见
1. Question聚合：Question作为聚合根，Answer作为内部实体。
   业务上回答不能脱离问题，该划分符合Sprint1业务需求通过。
2. User身份聚合：用户身份独立为一个聚合，负责登录身份信息通过。

## 2. 限界上下文评审意见
- Identity身份上下文：处理登录、用户身份
- QA问答上下文：处理问题发布、回答提交
> 上下文按照**业务能力划分，不是按前端/后端技术包划分**，符合实验要求通过。

## 3. 统一语言术语表评审
1. 所有业务名词中英对照，名词定义唯一，没有一词多义。
2. 没有混入Controller、Mapper这类技术名词。

## 最终业务结论
领域模型完全匹配Lab2确定的Sprint1 MVP范围，业务层面审核通过，可以合并。
